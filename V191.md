# UBos 1.91

The reported MODULE_NOT_FOUND for /home/ubos-os/start indicates Node was given a program entry named start. The correct UBos runtime command is node-start; node main.js executes the bundled example. This patch treats node start as a convenience runtime-start alias only if there is no actual runtime file named start. Existing files named start retain normal Node execution behavior. No missing module is falsely marked as a successful process.

The exported boot helper prepares scripts.start = node main.js only for the bundled package named ubos-os-beta when no start script exists and main.js is readable. It preserves other scripts and imported/custom project names. Terminal routes Node/npm through this helper before dispatch. npm start for a custom project retains that project's normal npm semantics. Package install success is still unverified.

Terminal display removes common complete ANSI CSI/OSC sequences and carriage returns. This is display cleanup, not a complete terminal emulator; escape sequences split across output chunks may still require a future streaming decoder.

UBos Browser shortcut add/edit/delete, bookmark editing/removal, history clearing, session restoration and bookmark-import confirmations now use asynchronous in-page dialog elements. Dialog requests are queued, use textContent for user data, restore focus, support keyboard submission and Escape/cancel, and never globally replace synchronous window.confirm with a Promise. Other OS/native dialogs remain unchanged. File selection still uses the browser/OS file picker. Open-in-Chrome and third-party website popups are not intercepted or bypassed.

This commit implements the changes but does not establish that the patch has been browser-tested or deployed. Test both node-start and node start, npm start on the bundled starter, a custom project with its own scripts, cancel/keyboard dialog behavior, and concurrent Browser controls.
