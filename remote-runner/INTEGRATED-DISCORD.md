# Integrated private Chrome and Discord preview

Port 7682 serves the actual UBos frontend on a private Codespaces origin. Its built-in **Browser** and installable **Google Chrome** apps both open the real Chrome stream inside UBos. The regular UBos site can embed the viewer inside the Chrome app window after its private preview URL is saved. Chrome is installed in the devcontainer image, and its profile is saved in ignored workspace storage `.ubos/chrome-profile`. GitHub private-port authentication protects the port; no UBos engine connection code or public GitHub token is used. The preview still streams the shared Linux desktop, not an isolated application surface. Browser data on this origin is separate.

After pulling main safely, rebuild the Codespace once so the devcontainer installs Google Chrome and applies the port configuration. Rebuilds can remove files and browser profiles outside `/workspaces`; back up important data first. After it reconnects:

```bash
node --test remote-runner/desktop-preview.test.mjs
```

On each Codespace start, `remote-runner/start.sh` starts both the terminal runner and the desktop preview. If GitHub CLI reports missing Codespaces authorization, run `gh auth login -s codespace` once in a Codespaces terminal and restart the preview using `bash remote-runner/desktop-preview-start.sh`. The preview enforces port 7682 Private before binding and writes startup diagnostics to `${XDG_RUNTIME_DIR:-/tmp}/ubos-remote-$UID/desktop-preview.log`; there is no engine connection code. Keep port 7682 Private. Keep ports 6080 and 7681 Private too; never forward raw VNC port 5901.

Open **Browser** or add **Google Chrome** from UB Store. In the regular public site, save the private port-7682 URL once; the viewer then opens inside the Chrome app window and starts Chrome automatically when the Codespace is already running. GitHub private-port authentication is required. A stopped Codespace cannot be awakened by the static UBos page; start it through GitHub first. The VNC desktop password may still be requested in the embedded viewer and is never saved by UBos. UB Store search and category filters help find launchers. Chrome diagnostics report whether the binary, desktop, version and process are available; CLI status commands report managed install/version information. Reinstalling Codex or Claude Code updates its managed package. The Chrome profile and sign-in data are stored in ignored `.ubos/chrome-profile` workspace storage, so they survive Codespace container rebuilds that preserve `/workspaces`. Back up important data before rebuilding or deleting the Codespace. Closing the last Chrome app window stops Chrome but keeps its profile. Closing the whole preview session or stopping the Codespace also stops Chrome; closing UBos does not stop Codespaces compute.

To use Discord, add it in UB Store and open its launcher. Enter the changed VNC password when requested. Verify the active server password file `/usr/local/etc/vscode-dev-containers/vnc-passwd` was changed from the public default. Running `vncpasswd` without a filename can change a different home-directory file. The prompt refuses the literal default but cannot verify the server configuration. Never share passwords or session files.

The browser view uses the GitHub-authenticated private-port noVNC stream and starts Chrome with its sandbox enabled; it does not expose a command API or turn arbitrary websites into trusted UBos content. Its clipboard bridge sends user-entered or user-pasted text to the remote desktop and can copy text received from the remote clipboard; clipboard contents are not persisted. The shared desktop may show other running Linux windows. Keep ports private and do not install untrusted HTML apps or scripts. The Chrome browser profile is persisted in workspace storage; the VNC password is never saved. Stop Codespaces compute through GitHub when finished.

The tests cover helper logic and a mocked browser lifecycle. A live Codespace rebuild, GitHub private-port authentication, X11/Chrome streaming, and Discord/audio/microphone behavior still require verification. Treat this as a preview, not production-ready.
