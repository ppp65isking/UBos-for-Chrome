# UBos 1.9

## In-OS Node/npm beta

Settings > Developer adds an opt-in Node/npm permission. This beta uses a single WebContainer in the main UBos document, shared by the Terminal and Node/npm app windows. The first node-start attempt asks permission to register the bundled isolation worker at the UBos project root, then reloads the desktop. After isolation, run node-start again and review network/runtime consent. The previously user-tested runtime/index.html is retained unchanged as a separate-tab fallback.

Project-wide isolation can change external resource, popup and iframe behavior. This is not equivalent to only isolating the /runtime area. It is not enabled merely by loading v1.9: worker registration requires explicit confirmation. The worker's default scope is the UBos project directory, not all GitHub Pages sites on the origin. It is coi-serviceworker 0.1.7, MIT license in runtime/coi-serviceworker.LICENSE.txt. Developer settings can unregister only the matching OS worker; close/reopen all UBos tabs afterward to release existing controllers. Removing a worker does not remove server-provided headers on other hosts.

node/npm commands use actual spawn output and exit codes. Network access is independent from the old virtual Terminal HTTPS switch. npm lifecycle scripts default to ignored; no malicious-code safety guarantee is made. Only trusted code and compatible packages should be used. The new integrated boot, package installs and export/import flows have not been browser-tested by this commit. Earlier separate-runtime Node/npm version and main.js tests do not prove the integrated path works.

Runtime files remain temporary and separate from UBos IndexedDB. node-write/cat/ls address the runtime. node-import copies up to 40 supported text files from a virtual folder, with confirmation; it skips binaries and can partially complete if a later file fails. node-export copies a runtime text file to a virtual path with confirmation. Existing backup behavior is unchanged. No automatic package/project persistence or preview-server app is added.

## App typography

Google Sans is applied to native UBos app interface documents using Google Fonts with anonymous CORS loading and a system-font fallback. Terminal output, code editors and code blocks retain monospace. Third-party embedded sites and sandboxed installed apps are not restyled. Availability depends on font resources and browser policy.

## Game startup

Game iframes stay visually hidden behind an accessible loading screen until the game module and selected game view are ready. Direct launches no longer intentionally reveal Gaming Hub first. A 20-second timeout provides a retry action instead of exposing an incomplete app. Runtime and visual behavior still require live testing.
